## GitHub review workflow

- After an authorized development phase is complete and its required tests have passed, commit the checkpoint and automatically push its dedicated review branch to `fargo161/first-encounter-lab`. Teddy’s standing approval covers that review-branch push and supersedes the local-only instructions in earlier run records. Each development phase still requires its own authorization.
- Before pushing, verify the independent Lab Git root, the GitHub remote and the intended review branch. Check the outgoing history for sensitive credentials or files. If tests fail, repository identity cannot be verified, or sensitive material would be published, stop and report.
- Preserve existing commits. Never force-push, rewrite history, or push sensitive credentials or files. This workflow authorizes pushes only to the dedicated review branch. Never automatically merge into `main`. The original First Encounter Game repository remains read-only under this authority.
- Verify that the remote review ref matches the local commit. Keep the README’s status, latest tested revision, open decisions and next authorization gate current. A successful push ends at review and grants no authority for the next phase.
